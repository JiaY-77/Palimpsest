# 任务：修复「记忆元数据硬加权」压过语义相关性（实测已完成，可直接实施）

## 背景

`core/trivium_store.py::TriviumStore.search_similar` 的排序分是：

```
final = cosine × importance × decay^(距创建天数/30)     （非 kb_chunk 节点）
final = cosine                                          （kb_chunk 节点，整条跳过加权）
```

问题：乘性因子取值范围约 0.25–0.90（跨度 > 3 倍），而候选之间的余弦分差通常只有
0.05–0.15（跨度 ≈ 1.5 倍）。**元数据的权重跨度大于语义分本身的跨度 → 排序由
importance/新鲜度主导，语义相关性被淹没。** 这不是衰减系数取值不当，而是
「乘性加权 + 尺度失配」的结构性缺陷。

## 实测数据（本地 embedding：qwen3-embedding:0.6b；138 题评测集，按层分层）

### 1. 真实检索接口对比：开/关硬加权（同一候选池、同一代码路径）

| 层 | 题数 | 现状（含硬加权）R@5 | 关闭硬加权 R@5 | Δ |
|---|---|---|---|---|
| hermes（记忆） | 38 | 0.2632 | 0.5789 | **+31.6pp** |
| kb（知识） | 40 | 0.7000 | 0.6500 | −5.0pp |
| novel（小说） | 20 | 0.9000 | 1.0000 | +10.0pp |
| other | 20 | 0.0500 | 0.6000 | **+55.0pp** |

结论：硬加权对记忆类节点是系统性负贡献；对知识类只有轻微的正贡献（因为
kb_chunk 被整条跳过加权，实际获得的是「别人被压低」的相对优势）。

### 2. 离线消融（全库候选，逐因子剥离）

| 层 | 纯余弦 cos | +importance | +importance+decay | 软加权（见方案） |
|---|---|---|---|---|
| hermes | 0.526 / 0.711 | 0.342 / 0.605 | 0.342 / 0.579 | 0.526 / **0.737** |
| kb | 0.275 / 0.750 | 0.025 / 0.100 | 0.025 / 0.125 | 0.250 / 0.700 |
| novel | 0.900 / 1.000 | 0.700 / 0.900 | 0.700 / 0.950 | 0.900 / **1.000** |
| other | 0.350 / 0.600 | 0.250 / 0.350 | 0.250 / 0.350 | 0.350 / 0.600 |

（单元格 = R@1 / R@5）

- importance 一项单独就造成 kb 层 R@5 0.750 → 0.100、hermes R@1 0.526 → 0.342
- 衰减在其上再叠加一层伤害
- 软加权（语义分为主线，元数据只做 ε 级 tie-break）把各层基本恢复到纯余弦水平，
  hermes/novel 还略有超出

### 3. 生产口径模拟（先按余弦取 30 候选，再加权排序取 top10，与 `search_similar` 同构）

| 层 | 现状 R@1 / R@5 | 软加权 R@1 / R@5 |
|---|---|---|
| hermes | 0.105 / 0.158 | 0.526 / 0.711 |
| kb | 0.450 / 0.750 | 0.300 / 0.750 |
| novel | 0.700 / 0.900 | 0.900 / 1.000 |
| other | 0.000 / 0.050 | 0.350 / 0.600 |

放大候选池（30 → 200）不产生任何差异，说明**问题只在排序公式，不在检索通道**。

### 4. 已排除的假设

| 假设 | 结论 |
|---|---|
| embedding 模型不匹配 | 否。库内向量与查询向量同源（cos ≈ 1.0000），模型自洽 |
| ANN 近似召回损失 | 否。`search_advanced(expand_depth=0)` 与精确余弦逐条一致（Pearson = 1.000，top20 完全相同） |
| 跨层竞争（kb_chunk 霸榜） | 次要。域内过滤只能带来 +5.3pp（hermes R@5 0.579 → 0.632） |
| 长节点粒度稀释 | 存在但非主因。把 gold 切块取 max 只能把 hermes R@5 从 0.579 提到 0.684，仍低于软加权 |

### 5. 已知代价（需在验收时复核）

kb 层 R@1 从 0.450 降到 0.300：40 题中有 6 题的原 top1（kb_chunk）被其它层的
记忆节点取代，且新 top1 与 gold 的内容 3-gram 重叠 < 0.05 —— 属于「同一问题的
另一个答案副本被排到前面」，不是内容错误，但评测口径会记为 miss。这是
「多答案」情形下无法自动判定的部分。

## 改动清单

### 1. `core/trivium_store.py`

`search_similar` 的加权重排改为**软加权**（加性、ε 量级）：

```python
final = cosine + eps × [clip((importance − 0.5) / 0.5, −1, 1) + decay^（距创建天数/30）]   # 记忆节点
final = cosine + eps × 1.5                                                                  # kb_chunk
```

- `importance_norm = clip((importance − 0.5) / 0.5, −1, 1)` → [−1, 1]
- `recency_norm = decay^（距创建天数/30）` → (0, 1]，直接可用，不需要全库统计
- `eps` 默认 0.02（相对余弦分差区间 0.05–0.15 是 13%–40% 的 tie-break 强度）
- kb_chunk 的 ε 倍率默认 1.5（实测取值：kb 层 R@5 在 1.5 时回到 0.750，取 1.0 时为 0.625）
- **保留旧行为开关**：新增配置 `MEMORY_RERANK_MODE = "soft" | "hard"`，默认 `soft`；
  `hard` 时走原乘性公式，可一键回退

### 1b. 候选层：排除 status="outdated" 的节点

`search_similar` 原先从全量节点取候选，其中约 24% 是已被新版本取代的
`status="outdated"` 节点（实测候选 top-30 里平均 7.2 个）。这些节点在展示层
本来就不出现，却占着候选名额。

- 候选倍数由 `top_k × 3` 提升为 `top_k × 6`，过滤后仍保留约 3 倍有效候选
- 过滤位置在 `search_advanced` 返回之后、加权重排之前，soft / hard 一致生效
- 新增 `include_outdated: bool = False` 参数：可追溯通道
  （`mem_search(include_outdated=True)`）显式传 True 时保留旧版本

### 2. `config.py`

- 新增 `MEMORY_RERANK_MODE`（默认 `"soft"`）
- 新增 `SOFT_RERANK_EPS`（默认 `0.02`，环境变量可覆盖）
- `MEMORY_DECAY_FACTOR` 保留（soft 模式下用于计算 `recency_norm`）

### 3. 测试

- 新增排序性质测试：
  - 语义分差大于 `2×eps` 时，元数据不得改变相对顺序
  - 语义分差小于 `eps` 时，高 importance / 新节点应排在前面
  - `MEMORY_RERANK_MODE="hard"` 时必须与旧公式逐位一致（回归保护）
  - `kb_chunk` 不受 `recency_norm` 影响（保持「知识不老化」语义）
- 全量 `pytest -q` 无新增失败

### 4. 评测

- 改动前后各跑一次 `eval/run_eval.py`（4 模式），把分层 R@1/R@5/MRR 写进
  `eval/docs/` 的对比表

## 验收标准

1. 四层 R@5 均不低于改动前，hermes / other 层 R@1 提升 ≥ 15pp
2. 全量测试通过；`MEMORY_RERANK_MODE="hard"` 可复现旧排序
3. 评测报告数字与本文档第 3 节的模拟方向一致（允许 ±5pp）

## 落地后实测（离线 Query Set，138 题按层分层，R@5）

| 层 | 改动前 | 只改软加权 | 软加权 + 候选排除 outdated |
|---|---|---|---|
| hermes（记忆） | 0.263 | 0.579 | **0.684** |
| kb（知识） | 0.700 | 0.675 | 0.700 |
| novel（小说） | 0.900 | 1.000 | 1.000 |
| other | 0.050 | 0.600 | 0.600 |

四层均不低于改动前；全量测试通过。

## 已知边界

- 软加成的单节点取值区间是 (−ε, 2ε]（`importance_norm ∈ [−1, 1]` 加
  `recency_norm ∈ (0, 1]`），因此两个节点元数据完全相反时最坏摆动约 3ε = 0.06。
  若需要把边界收紧到 2ε，可把 `importance_norm` 改为 [0, 1]（只加分不减分）。
- 写入侧冲突检测的非事务路径（`core/conflict.py` 未传 `include_outdated` 时）
  同样看不到 outdated 节点；主写入路径走事务内 `db.search`，不受影响。
