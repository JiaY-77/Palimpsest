# 分块重打分续四：索引期 small-to-big（块级召回 → 节点级返回）

## 问题

前三轮（`09` / `10` / `11`）否证的都是**检索期近似**：先把节点切块、把块分塞回节点空间
再与整条余弦比较。那条路线必须解决「跨域分数不可比」，而三轮都没找到能站稳的校准形式。

索引期方案在机制上不同：**块作为独立实体建索引、独立参与检索竞争，命中后返回其父节点**。
块与块之间分数天然可比，不需要跨尺度校准——按此逻辑它应当绕开前三轮的全部麻烦。
本轮用离线探针实测：不动生产索引，只回答「值不值得上生产」。

## 方法

同一份真库快照副本（875 节点 / 704 个 active 且有正文 / 309,692 字）：

- 全库切块 `chunk=400 / overlap=100` → **1278 块**（= 节点数 ×1.82），块向量独立嵌入
  （`qwen3-embedding:0.6b`）
- 块级检索 top-K 块 → 按父节点取最大块分（`max` 聚合）→ 节点级排序返回
- 对照：节点级整条余弦（`content[:4000]` 重嵌入，与前三轮 base 同口径）
- 补充对照（判断瓶颈位置用）：
  - `node_candN`：节点级只取前 N 个候选后排序（同预算对照）
  - `chunkN_rerank`：块召回父节点集合、最终用整条余弦重排（块只当候选扩展器）
  - 块级召回上限：gold 节点至少有一个块进入 top-K 块集的比例

## 成本面（均非障碍）

| 指标 | 实测值 |
|---|---|
| 块数 | 1278（节点数 ×1.82） |
| 块向量矩阵 | 5.0 MB（float32 原始）/ 4.6 MB（npz 缓存） |
| 索引体积外推 | ≈ 11.3 MB（按现库 9.1 KB/节点同口径外推） |
| 构建耗时 | 节点级 30.3s；块级 36.6s |
| 检索延迟 | 节点级 0.15 ms；块级 top180 检索+聚合 0.22 ms |

块级召回上限（gold 有块进 top-K 块集）：**top30 87.3% / top60 90.7% / top180 98.3%**。

逐题归因（`chunk_top180` 相对 node）：**gain 3 / loss 7**，7 个损失里 **6 题是 kb**，
3 个增益里 2 题是 hermes（与前三轮同型的「kb 掉、hermes 涨」）。

## 关键诊断

1. **召回不是瓶颈**：块级召回上限 98.3%（top180）——gold 的块几乎总能被检索到；
   而节点级**候选预算 30 就已等于全量排序**（`node_cand30` 与 `node` 逐位相同）。
   也就是说：本库在 704 节点规模下，候选池不是任何东西的瓶颈。
2. **损失全部来自排序**：`max` 聚合把长节点的位置打乱——块数随长度增长，
   长节点有更多「抽到高分块」的机会，非 kb（尤其 hermes）被抬高，kb 被挤出
   （kb R@5 0.725 → 0.600，−12.5pp）。这与检索期分块（`09`/`10`）的失效机制**完全同型**。
3. **换回整条重排后逐位等于节点级**（`chunkN_rerank` ≡ `node`）：
   说明块级召回**在这个库上没有任何增益空间**——它带来的候选不比节点级候选多。
4. **元结论（动机层面的否证）**：分块路线的原始动机是「长节点整条余弦被平均稀释、
   块级匹配能救」。本库数据不支持这个动机——节点级整条排序已能把 gold 排进 top-5
   （R@5 0.7542），块级重打分只引入偏置，不带来召回。

## 结论

**索引期 small-to-big 在 Palimpsest 上否证**：成本可接受（+11.3 MB、+37s 构建、+0.07 ms 延迟）、
召回非瓶颈（上限 98.3%、候选预算 30 已足够）、排序纯损失（−3.39pp R@5、kb −12.5pp）。

至此**分块 / small-to-big 整条路线四轮全部否定**（09 长度归一化与分层分块、10 分数校准、
11 校准细化、12 索引期块级召回），整条路线关闭——它的核心假设（粒度错配是真瓶颈）
在本库数据上不成立。

## 已知边界

- 只测 `chunk=400 / overlap=100` 与 `max` 聚合；`mean_top2` 等聚合形式在检索期已否证（`09`），
  未在索引期重测（结论方向一致，重测优先级低）。
- 库规模 875 节点 / 704 active。库继续增长、出现更多超长节点时，本结论可能需重验
  （`node_cand30 ≡ 全量` 这一条尤其依赖当前规模）。
- 单轮数据；R@10 与 MRR 在并列分数处有抖动（本次 MRR 0.6017 / 0.6044 两次运行的差异即此）。
- 块向量缓存 `eval/.tmp/chunk_index_vectors.npz` 只用于复跑加速，不入库。
