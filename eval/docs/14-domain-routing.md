# 查询侧域路由（域过滤 / 同域软加权）：收益真实，但不可自动推断

## 背景

域内过滤曾被记为跨层竞争的缓解手段，旧排序（元数据硬加权）下只带来 +5.3pp
（hermes R@5 0.579 → 0.632，见 `05-ranking-reweight.md`），当时判定为「次要因素」。
当前是干净语义序（`expand_depth=0`、ε 级软加权），需要重测；并且真实场景里
**域是自动推断的**（用户不会手填域），推断错误会直接变成 miss——
所以本轮同时量三件事：天花板（域正确时）、自动推断的实际效果、以及最坏情况伤害。

## 方法

同库快照副本（706 个 active 且有正文的节点）、同题集（118 正样本）、
同 embedding 模型。`payload.domain` 归并为 5 类：
`rule→hermes`、`由佳→novel`、`tms/work→task`，其余原样（`hermes / kb / novel / task / general`）。

| 变体 | 定义 |
|---|---|
| `base` | 全库排序，不过滤 |
| `oracle_hard` | 用真实域硬过滤候选（天花板，不可上线） |
| `oracle_soft` | 用真实域对同域候选软加权（boost 0.02 / 0.05 / 0.10 / 0.20 四档扫描） |
| `wrong_soft_b10` | boost 加在**错误的域**上（风险上界） |
| `llm_hard` / `llm_soft` | 用本地 `qwen2.5:7b-instruct`（temperature=0）推断域后硬过滤 / 软加权 |
| `maj_hard` / `maj_soft` | 用「全库 top-10 候选的多数域」推断后硬过滤 / 软加权 |

## 关键发现

1. **收益真实且可观**：域正确时 R@5 **+6.78pp**、R@1 **+8.47pp**、MRR +8.90，
   逐题 **+8 / −0（零损失）**。比旧排序时代（+5.3pp）更大——干净排序后跨域竞争
   成了更纯粹的损失源。
2. **软加权 = 硬过滤**：`boost=0.10` 时软加权的聚合指标与逐题结果**与硬过滤完全相同**，
   而软加权不会排除跨域候选 → 落地应选软加权（`0.10` 与 `0.20` 同效，说明已饱和）。
3. **自动推断不可行**：LLM 分类准确率仅 37.3%，`llm_soft` 落到 −0.85pp、
   `llm_hard` −43pp（误判即 miss）。这不是 prompt 问题——本库的域语义本身就重叠。
4. **风险量级清晰**：域完全错时 R@5 −27.12pp（32 题损失）是上界；
   37% 准确率的混合伤害只有 −1.69pp（对的收益与错的损失部分抵消）。
5. **结论**：这条路线**不需要自动推断**——生产接口本来就有显式 `domain` 参数，
   调用方（知道自己在问哪个域）传参即可。要做的只是在「显式指定域」时
   给同域候选软加权 `+0.10`。

## 落地建议（待批准，涉及生产排序）

- `mem_search` / `kb_search` / `mem_retrieve` 在**调用方显式传入 domain** 时，
  对同域候选加 `+0.10` 软加权（不是硬过滤），与既有 `SOFT_RERANK_EPS` 同一机制；
- **不做**自动域推断；
- 验收要求：真实接口双向验证（指定域 / 不指定域各跑一次）、保留开关（默认关或可回退）、
  实测回退值复现旧数字。

## 边界

- 域定义来自 `payload.domain` 归并；`由佳` / `tms` / `work` 等小域样本极少。
- 单轮数据；R@1 有 ±1 题抖动（`oracle_hard` 两次运行 +9.32 / +8.47）。
- boost 只扫了 4 档；未测「按域粒度加权」（各域不同 boost）。
- 只在离线近邻排序上验证，未接入生产接口。

## 复现

```bash
venv/Scripts/python.exe scripts/domain_routing_probe.py            # 全量 118 题

```
