# 检索质量评测

> 本文说明 Palimpsest 的离线检索质量评测体系：**题集怎么造、指标怎么定义、结果怎么读**，以及如何复现。
>
> 评测数据来自真实运行库。为保护个人数据，**原始题集与逐题结果不入库**（`.gitignore` 排除 `eval/*.json` 与 `eval/report_*.md`）；本文公开的是**方法**与**汇总结论**。
>
> 代码与实验记录见 [`eval/`](../eval/)（评测脚本、指标纯函数、14 份实验文档）。

---

## 一、为什么要自建评测

检索这类改动（切片粒度、融合方式、重排权重）有个通病：**「感觉变好了」不是证据**。

- 改了参数后，主观上「搜得更准了」很常见，但它可能只是**记住了改完后的那几条查询**；
- 多路检索（语义 / 全文 / 图谱）之间的权重关系更难凭直觉判断——某一侧权重抬一点，另一侧就相对被压；
- 没有对照，就无法回答「这次改动到底改善了什么、代价是什么」。

因此需要一套**可重复、有对照、能归因**的离线评测。

## 二、评测体系设计

### 2.1 题集构造（防作弊是重点）

题集由**库内真实节点反推**生成，而不是人工编题：

| 要点 | 做法 | 为什么 |
|---|---|---|
| 反推查询 | 取真实节点，让模型生成「用户会怎么问才能问到这条」 | 保证每题都有确定的正解，且查询分布贴近真实使用 |
| **禁止抄原文** | 生成后校验与原文的公共连续子串，**严禁 ≥6 字** | 否则测的是「字面抄写」，不是「语义检索」——这是评测有效性的关键 |
| 两类交替 | 口语化改写 / 含术语实体 | 覆盖「模糊问」与「精确问」两种真实形态 |
| 负样本 | 约 20 条，询问库中**确实不存在**的主题 | 衡量「不该召回时会不会乱召回」 |
| 固定随机种子 | 抽样与生成可重现 | 换机器、换时间跑，题集不变 |

题集按**层**打标签（记忆 / 知识库 / 小说 / 其他），便于分层报告——不同层的数据形态差异很大，混在一起算平均会互相掩盖。

### 2.2 四种检索模式对照

同一题集跑四条路径，横向对照：

| 模式 | 说明 |
|---|---|
| `fts` | 纯全文检索 |
| `vec` | 纯语义向量检索（不启用图扩散） |
| `rrf` | 融合排序（语义排名 + 全文排名的 reciprocal rank 求和） |
| `cascade` | 级联（全文粗筛 → 语义精排） |

**对照的意义**：能回答「融合到底有没有用」「级联在什么场景下更优」，而不是只证明「我那套能跑」。

### 2.3 指标定义

| 指标 | 定义 |
|---|---|
| Recall@K | 前 K 个结果中命中正解集合的比例 |
| MRR@K | 第一个命中结果的倒数排名（无命中记 0） |
| nDCG@K | 归一化折损累积增益（正解 1.0，同文档的其他切片 0.5） |
| **doc_recall@K** | 知识库题专用：同一来源文件的**其他切片**也视为相关（二值口径） |
| **正负样本可分离度（AUC）** | `P(随机正样本分数 > 随机负样本分数)`；0.5 = 完全无法区分，1.0 = 完美可分 |

最后一项是本体系的特色：**大多数评测只算召回，不问「误召回」**。有了负样本与可分离度，才能同时看到「该找的找到没有」和「不该找的有没有乱找」。

### 2.4 只读自证

评测全程在**库副本**上运行（脚本启动时复制库与 sidecar 文件，并把环境变量指向副本），避免污染真实数据；同时对真实库文件**跑前跑后各算一次 SHA256 并写入报告**，一致才标记通过。

> 这一条不是形式主义：评测会触碰 `hit_count` 之类的写入路径，直接跑真库会改变运行数据。

## 三、结果

### 3.1 整体指标（自评口径，含口径说明）

最新一轮全量评测（138 题，`vec` 单模式）的主要指标：

| 指标 | 值 |
|---|---|
| Recall@1 / @3 / @5 / @10 | 0.170 / 0.237 / 0.246 / 0.263 |
| MRR@10 | 0.203 |
| nDCG@5 | 0.212 |

**这个数字不高，且需要连同口径一起读**：

1. **题集是严格反推**（禁止抄原文），查询表述与原文的词汇重叠被刻意压到最低；
2. **全库跨层竞争**：记忆节点、知识切片、小说设定在同一候选池里抢排名，而题集里各层混合；
3. 因此这套数字衡量的是「**在一个混合的真实库里，语义检索单独作战能到什么程度**」，**不是**在公开 benchmark 上的表现，也不适合与其它系统的自报数字横向比较。

引入分层与文档级口径后，图景会清楚很多（见 3.2）。

### 3.2 分层结果

同一轮评测按层拆分（Recall@5）：

| 层 | Recall@5 | 说明 |
|---|---|---|
| 知识库（kb） | 0.550 | 且**文档级** `doc_recall@5` = **0.815**——即 top-5 里命中同一来源文件的比例超过八成 |
| 记忆（hermes） | 0.132 | 长文本记忆节点与短查询的粒度错配是主因（见 3.3） |
| 小说设定 | 0.050 | 该层数据形态特殊（人物卡高度相似），语义区分度天然低 |
| 其他 | 0.050 | 样本量小 |

**怎么读**：知识库场景（文档问答类 RAG 的典型场景）表现明显更好——**文档级召回 0.815 是这个体系里最有实用意义的一个数**；而记忆层的低分，正是下一节那项修正的起点。

### 3.3 消融实验：一次结构性修正

记忆层得分偏低，最初怀疑是衰减参数没调好。但分层消融给出了另一个答案：

**诊断**：原排序公式是**乘性硬加权**——

```
final = cosine × importance × decay^(天数/30)
```

其中元数据因子的取值范围约 0.25–0.90（跨度 > 3 倍），而候选之间的余弦分差通常只有 0.05–0.15（跨度约 1.5 倍）。**元数据的权重跨度大于语义分本身的跨度** → 排序被重要度与新鲜度主导，语义相关性被淹没。

这是**尺度失配**的结构性问题，不是参数取值问题。

**修正**：改为 **ε 级加性软加权**——语义分是主线，元数据只做小幅 tie-break：

```
final = cosine + ε × [归一化重要度 + 归一化新鲜度]        # ε 默认 0.02
```

同时把已被取代的旧版本节点从候选池中排除（原先约 24% 的候选是这类节点，占着名额却不展示）。

**对照结果**（138 题按层分层，Recall@5；此表为离线消融口径）：

| 层 | 改动前 | 仅软加权 | 软加权 + 候选排除 |
|---|---|---|---|
| 记忆（hermes） | 0.263 | 0.579 | **0.684** |
| 知识库（kb） | 0.700 | 0.675 | 0.700 |
| 小说设定 | 0.900 | 1.000 | 1.000 |
| 其他 | 0.050 | 0.600 | 0.600 |

**结论**：记忆层 Recall@5 提升约 2.6 倍，其余各层不倒退。**"语义为主、元数据为辅"这条原则，是用数据定下来的，不是设计时拍脑袋定的。**

**另一项同样重要的结论**：分块重打分的分数校准路线，前后做了三轮共 15 个变体，全部增益都在「≤1 题」的量级。据此判定该路线已到边际、**主动停止**——避免在一个收益与噪声同阶的方向上继续投入。

## 四、已知局限

1. **自评口径，非公开基准**：题集由本库反推，不能与 LoCoMo 之类的公开基准直接比较。
2. **题集规模有限**（百量级）：单个变体的差异若只有 ±1 题，不足以作为方向性证据；报告中凡涉及此类差异均标注了。
3. **分层不均衡**：小说层与「其他」层样本量小，其分数仅供参考。
4. **单次快照**：结果依赖当时库内数据分布；换库需重跑。
5. **幻觉率未直接度量**：本体系用「正负样本可分离度」间接衡量误召回风险，但没有端到端评估生成阶段的事实性。

## 五、如何复现

```bash
# 0. 前提：已装好依赖、Ollama 拉取了本地向量模型
venv/Scripts/python.exe eval/gen_eval_set.py            # 生成题集（需 LLM API）
venv/Scripts/python.exe eval/run_eval.py --modes vec,rrf,cascade
venv/Scripts/python.exe eval/run_eval.py --limit 20     # 快速冒烟

# 指标纯函数单测（不联网、不连库）
venv/Scripts/python.exe -m pytest tests/test_eval_metrics.py -q
```

产物：`eval/results_<UTC 时间戳>.json`（逐题排名）与 `eval/report_<时间戳>.md`（对照报告，含库 SHA256 一致性检查）。两者含个人库内容，故不入库。

## 六、小结

| 设计决策 | 依据 |
|---|---|
| 自建评测而非凭感觉 | 「感觉变好」无法排除记忆偏差 |
| 题集禁止抄原文 | 保证测的是语义检索，不是字面匹配 |
| 加入负样本与可分离度 | 同时衡量漏召回与误召回 |
| 分层报告 | 不同层数据形态差异大，混算会互相掩盖 |
| 语义为主、元数据为辅（ε 级加性） | 消融实验：原乘性加权存在尺度失配，修正后记忆层 R@5 0.263 → 0.684 |
| 评测在库副本上跑 + SHA256 自证 | 评测会触发写入路径，不能碰真实数据 |

*本页只公开方法与汇总结论；原始题集、逐题结果与含个人数据的报告保留在本地。*
