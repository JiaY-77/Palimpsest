# 长期支持（LTS）与版本策略

> 本文定义 Palimpsest 的版本承诺：**哪个版本可以放心长期使用、承诺什么、承诺多久**。
> 当前 LTS：**v2.20.0**（首个）。发布流程见 [RELEASING.md](RELEASING.md)，历史变更见 [CHANGELOG.md](../CHANGELOG.md)。

---

## 一、LTS 承诺

锁定一个 LTS 版本，可以一直用下去，不用担心接口变、行为变、数据格式变。

| 承诺 | 内容 |
|---|---|
| **接口冻结** | 稳定清单内的 REST 路由 / MCP 工具 / CLI 命令，名字、参数、返回结构不变 |
| **行为冻结** | 默认行为不变（默认检索层、默认注入策略、默认配置值都不动） |
| **格式冻结** | 库文件组格式不变；老库能被新补丁版本直接打开，无需迁移 |

**不承诺**：新功能、性能提升、内部实现与模块结构、标注为实验性的接口。

---

## 二、版本号规则

```
v2.20.0            ← 首个 LTS 起点，契约在本版定义
v2.20.x ~ 2.30.x   ← 全部「适配 2.20」：只加不删、默认行为不变、数据格式不变
v2.31.0 起         ← 允许「小破坏性」变更（不兼容 2.20 契约，但不升主版本）
v3.0.0             ← 大破坏性变更（存储格式、核心接口重构、数据模型重写）
```

| 区间 | 允许什么 | 对用户意味着什么 |
|---|---|---|
| **2.20.x ~ 2.30.x** | 修 bug、加工具、加路由、加配置项（默认值不动） | 锁在 2.20 上一直用没问题；升级到这段内任何一版都不用改代码、不用迁数据 |
| **2.31.0 起** | 删实验性接口、改非核心默认值、payload 字段改名（须给迁移说明） | 想继续吃新功能得读升级说明；不想动就留在 2.30.x |
| **3.0.0** | 存储格式变更、核心记忆接口重构、数据模型重写 | 必须走迁移脚本 + 回滚演练 |

**「小破坏性」的边界**（防止 2.31 变成第二个 2.0）：

- **可以**：删第三级（实验性）接口、改非核心配置默认值、payload 字段改名（保留读兼容）
- **不可以**：动存储格式、动第一级稳定接口的名字与签名、动检索默认行为

**另外三条硬规则**：

1. **2.20.0 ~ 2.30.x 期间不出现任何破坏性变更。** 想做破坏性的事，要么等 2.31，要么进 3.0。
2. **补丁号（`x.y.z` 的 `z`）只承载修复**，不改任何对外行为。
3. **每条 LTS 线有明确的 EOL**（见第四节）。

> **想长期不动的人，锁 2.30.x 比锁 2.20.0 更划算**——同样兼容 2.20 契约，但白捡整条 LTS 线的 bug 修复。

## 三、承诺范围（三级分级）

### 第一级 · 稳定契约（LTS 内绝不改）

**记忆核心**

| 类别 | 内容 |
|---|---|
| REST | 记忆写入 / 检索（`/mem/search`、`/mem/hybrid-search`）/ 单节点读写（`/memory/{id}`）/ 最近列表 / 图谱（邻居、社区）/ 建边删边 / 统计 / 导出 / 健康探针 |
| MCP | 对应的记忆工具（`mem_ingest` / `mem_search` / `mem_hybrid_search` / `mem_recent` / `mem_link` / `graph_*` / `mem_stats`） |
| CLI | `ingest` / `search` / `hybrid-search` / `recent` / `graph` / `link` / `stats` / `export` |
| 存储 | 库文件组（`.db` + `.vec` / `.gidx` / `.pidx` / `.pld.*` / `.wal` / `.flush_ok`）格式 |
| 配置 | 记忆核心配置键（检索权重、`tier`、embedding 相关） |

**知识库、胶囊与任务**

| 类别 | 内容 |
|---|---|
| REST / MCP / CLI | 知识库检索与索引、会话胶囊（生成 / 读取 / 补写 / 接手留痕）、任务节点状态查询 |
| 配置 | `PALIMPSEST_*` 插件配置键 |

**记忆包交换（MemoryHub）**

导出 / 导入的包格式、字段语义、入籍规则。格式一变，别人存过的包就读不了——比接口改名更伤人，因此冻住。

**记忆治理**

`consolidate`（容量自动合并）、`promote`（高频记忆升权）。**算法内部可以调**，但对外行为与配置键不变：默认 dry-run、`--apply` 才执行、阈值配置键名不变。

### 第二级 · 向后兼容扩展

- 新增 MCP 工具 / REST 路由 / CLI 命令
- 新增配置项（默认值必须保持旧行为）
- 新增 payload 字段（读侧必须容忍缺失）

### 第三级 · 实验性（可能变，不构成承诺）

- `/report`（依赖外部模型，输出随模型变）
- `/summary`（摘要格式随场景演进）
- `eval/` 下的评测工具与题集格式
- dashboard 页面
- 所有内部模块结构与函数签名

> 实验性接口在 [API.md](API.md) 中以 `**[实验性]**` 标注；**未标注的一律属于第一级**。

## 四、支持策略

| 项 | 规则 |
|---|---|
| 每条 LTS 支持时长 | **12 个月**，从发版日起 |
| 修什么 | 数据损坏、安全漏洞、核心功能不可用 |
| 不修什么 | 新功能、性能优化（除非造成不可用）、实验性接口的问题 |
| 补丁节奏 | 有问题就发，无固定周期 |
| EOL 政策 | 下一个 LTS 发布后，旧 LTS **再支持 6 个月**；之后只留文档，不再修 |

---

## 五、文档版本

每个 LTS 有对应的文档快照：

- 仓库内：`docs/versions/v2.20/`（只读归档，发布后不再修改）
- 当前版本文档：`docs/` 根目录（跟随 main 分支演进）
- `CHANGELOG.md`：LTS 版本在标题行显式标注 `· LTS`

## 六、升级路径

### 2.19.x → 2.20.0（零破坏）

直接升级即可：无破坏性变更、数据库无需迁移。

### 2.20.x → 2.30.x（同一条 LTS 线）

直接升级即可：只加不删，默认行为不变。

### 2.30.x → 2.31.0 起（小破坏性）

先读 `CHANGELOG` 的「破坏性变更」小节；不想动就留在 2.30.x。

### 任意 2.x → 3.0.0（大破坏性）

必须满足三条，缺一不可：

1. 提供迁移脚本 + 回滚方案，且在**真实库副本**上验证过
2. 存储格式写入显式 `schema_version`，能检测「新库 + 老代码」误配
3. 有升级指南，写清哪些用法会断、怎么改

## 七、历史阶段说明

| 阶段 | 版本 | 状态 |
|---|---|---|
| 内部迭代 | 1.0.0 之前 | 未对外发布 |
| 开发期 | **v1.0.0（2026-08-29）~ v2.19.0（2026-10-29）** | 对外可用，但接口随需调整；不含长期承诺 |
| **LTS** | **v2.20.0 起** | 承诺见本文 |

> 开发期确实发生过破坏性变更（v2.0.0 移除了整个「规则域」、检索默认改为只回事实层、插件注入默认收敛），因此那些版本不构成长期承诺。**从 v2.20.0 起，承诺生效。**
